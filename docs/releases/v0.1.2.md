# Loopbee v0.1.2

## 新增功能

- **支援更多 agent CLI**：除了 Codex CLI 和 Claude Code，現在也能用 **Gemini CLI**、**OpenCode** 和 **pi** 執行 Loop。每個 CLI 只開放它自己能真正強制執行的權限等級：Gemini CLI 四種都有（可寫入等級能改檔、不能執行 shell 指令；加上網路等級才能執行指令），OpenCode 和 pi 沒有沙箱，只能用「唯讀」或「代理自己的設定」。選了 agent 做不到的等級，Loopbee 會拒絕並列出可用的等級，不會在沒有保護的情況下照跑。
- **模型與 token 用量**：Loop 可以指定模型（留空則用 agent 預設）。每個 agent 步驟都會記錄 CLI 回報的模型與 token（輸入、快取、輸出），有回報費用時一併顯示；Run 頁面顯示總量與每一步，Loop 頁面彙總近 7 天與 30 天，按模型列出。Loopbee 不自行估算價格。
- **今日頁面改成看板**：四欄依工作流向排列：「即將執行 → 執行中 → 等你處理 → 今日完成」，失敗或被阻擋的 Run 會停在「等你處理」直到有人查看；上方新增「今日 token」，下方列出今日各 agent 與模型的用量。

- **Loop 也能用到你自己 agent 裡的東西**：每次執行都能讀取代理自己的 skill、plugin、子代理、指令、CLAUDE.md / AGENTS.md 與專案記憶（worktree 中也會指出專案記憶的位置）。Claude Code 在唯讀等級也能載入 skill。
- **可讀路徑**：Loop 可以列出專案以外、代理只能讀取的資料夾或檔案，例如 skill 的憑證資料夾 `~/.pi/agent/private`。`~/.ssh`、`~/.aws` 等電腦憑證位置一律拒絕。
- **複製到 worktree**：全新 worktree 缺少的 `.env`、本機設定等被 Git 忽略的檔案，可以從你的 checkout 複製過去，而且永遠不會被提交；`CLAUDE.local.md`、`.claude/settings.local.json` 會自動複製。
- **使用 shell 裡的環境變數**：環境變數可以寫成 `env:名稱`，Loopbee 找不到時會向登入 shell（Windows 則是使用者環境變數）查詢，不必再於每個 Loop 手動填值。
- **代理拿不到什麼，一眼就知道**：被阻擋的 Run 會列出代理需要但拿不到的東西（檔案、主機、變數、工具），並說明怎麼給 Loop 存取權；通知也會附上。
- **beectl cancel / delete**：`beectl cancel RUN [--wait]`、`beectl cancel --loop 名稱`、`beectl delete 名稱 --yes`，以及給腳本用的 `beectl run 名稱 -q`（只輸出 Run ID）與 `beectl runs --status`。
- **使用代理自己的 MCP 工具**：每個 Loop 新增一個開關。代理平常透過 MCP 使用的瀏覽器、資料庫、主控台等工具，在無人值守的執行中沒有人能按「允許」，以前會被直接拒絕（例如 Codex 後台模式固定是 `approval_policy=never`）。開啟後 Loopbee 會依各代理的方式預先核准全部 MCP 工具；關閉時在 agent-config 以下的等級停用它們。Loopbee 本身不提供瀏覽器，代理用它原本習慣的工具。被拒絕的工具呼叫會出現在「代理拿不到」清單裡。
- **審核後的步驟可以執行已審核的變更**：審核關卡核准後的指令步驟，現在可以執行代理在關卡前改過的檔案（例如已審核的 migration 或部署腳本），讓「合併 → 審核 → 遷移 → 部署」能在同一個 Loop 完成；審核前仍然拒絕。

- **自動更新**：發布版會在啟動後及每六小時檢查 GitHub 上的新版本，下載後以發布時公布的 SHA-256 核對，再於你重新啟動（有 Run 在執行時會等它們結束）或結束 Loopbee 時安裝。設定 › 一般 › 更新可以立即檢查、關閉自動更新。從原始碼建置的版本不會自動更新。做法參考 magpie 的更新機制。

## 修正問題

- `beectl version` 和 `beectl --version` 現在可在 Loopbee 未啟動時顯示 beectl 自己的版本；`beectl help` 也列出這兩種用法（#1）。新增回歸測試與 LESSONS.md 規則，確保本機版本查詢不依賴應用程式連線。

- 在 Windows 上，Claude Code 在可寫入等級的 Loop 會因「Sandbox required but unavailable」失敗，而 CLI 的建議無法套用。現在錯誤會說明可行的做法（改用 Codex、WSL2 或 agent-config），編輯器也會事先提醒。
- 多個 Loop 同名時，`beectl run 名稱` 會默默啟動其中第一個；現在會拒絕並列出各自的 ID。
- 刪除 Loop 時，它的 worktree 仍登記在你的 repository 裡，keychain 中的 secret 也沒被刪除；現在會一併清除（分支保留）。
- 缺少 `env:` 環境變數時的錯誤訊息寫成「notification environment variable is not set」；現在會指出是哪個變數、該在哪裡設定。
- 用 pi（或其他沒有沙箱的代理）以聊天建立 Loop 時，設計者可能提出代理無法強制的權限等級，導致草稿無法儲存；現在設計者會被告知該代理可用的等級，Loopbee 也會把過高的等級往下調並在回覆中說明。
- 設定裡只能把 Codex 或 Claude Code 設為預設代理，選 Gemini CLI、OpenCode 或 pi 會失敗；現在所有支援的代理都可以。
- Codex 用聊天建立修正類 Loop 時，可能提出只有指標名稱、沒有 JSON 路徑的驗證步驟，導致草稿無法儲存；現在只有一半的指標設定會被忽略。
- 代理 CLI 已安裝但無法啟動時（例如安裝損壞、啟動即被 macOS 終止），設定頁只顯示「未偵測到」；現在會顯示「無法使用」與失敗原因及修正方式。

## 下載與安裝

| 平台 | 下載檔案 | 使用方式 |
|---|---|---|
| Windows 10/11 x64 | `Loopbee-windows-amd64.exe` | 直接執行桌面程式。建議先放到固定位置再開啟，因為「登入時啟動」和自動更新都會使用這個路徑 |
| Windows 10/11 x64 | `Loopbee-windows-amd64.zip` | 可攜版：桌面程式 `loopbee.exe`、無介面版 `loopbee-nogui.exe` 和 `beectl.exe` |
| macOS Apple Silicon（M 系列） | `Loopbee-macos-arm64.dmg` | 打開後把 Loopbee 拖到「應用程式」 |
| macOS Apple Silicon（M 系列） | `Loopbee-macos-arm64.zip` | 同一個 App 的壓縮檔 |
| macOS Intel | `Loopbee-macos-amd64.dmg` | 打開後把 Loopbee 拖到「應用程式」 |
| macOS Intel | `Loopbee-macos-amd64.zip` | 同一個 App 的壓縮檔 |
| 全部 | `SHA256SUMS` | 所有下載檔案的校驗碼。用 `shasum -a 256 檔名`（macOS）或 `Get-FileHash 檔名`（Windows PowerShell）算出雜湊值，和這個檔案裡同名那一行比對 |

不確定 Mac 是哪一種晶片：點左上角蘋果選單 ›「關於這台 Mac」，「晶片」寫 Apple M 系列就下載 arm64，寫 Intel 就下載 amd64。

- **從 v0.1.1 或更早升級**：舊版沒有自動更新，這一版請手動下載並覆蓋原本的程式；資料會沿用。之後的版本會自動更新。
- **Windows**：需要 Microsoft Edge WebView2 Runtime（Windows 10/11 通常已內建）。若要使用 `beectl`，請下載 ZIP。要自動更新，程式所在的資料夾必須是你能寫入的（例如不要放在 `C:\Program Files`）。資料在 `%APPDATA%\loopbee`。
- **macOS**：安裝檔沒有簽章，第一次開啟時在 Finder 對 `Loopbee.app` 按右鍵選「打開」，或到「系統設定 › 隱私權與安全性」選「強制打開」。請從「應用程式」資料夾開啟：直接從「下載」或磁碟映像執行時，macOS 不允許 App 更新自己，設定頁會說明原因。資料在 `~/Library/Application Support/loopbee`。
- **Agent**：請先安裝並登入要使用的 agent CLI（Codex CLI、Claude Code、Gemini CLI、OpenCode 或 pi）。

## 已知限制

- Codex 在 Windows 上的沙箱能否讀取工作目錄以外的路徑尚未驗證；如果「可讀路徑」在 Windows + Codex 下仍然讀不到，請改用 agent-config 權限。
- 自動更新只會從這一版之後的發布版本開始生效（這一版本身要手動下載）；macOS 與 Windows 的實際更新流程、管理員密碼提示、防毒軟體鎖檔的情況都還沒在真機上驗證。
- Codex 只能預先核准定義在 `~/.codex/config.toml` 或外掛裡的 MCP server；定義在其他設定層（例如專案的 `.codex/config.toml`）的 server 要在那裡設定 `default_tools_approval_mode = "approve"`，被拒絕時「代理拿不到」清單會這樣提示。
- 「使用代理自己的 MCP 工具」依各 CLI 的原始碼實作，目前只用模擬 CLI 測試過；發布前需要用真的 Codex、Claude Code、Gemini CLI、OpenCode、pi 各跑一次。Codex 的公開 issue 回報 macOS 上 workspace-network 的網路設定可能被忽略，也要一併確認。
- pi 已用真正的 pi 1.1.0 在 macOS 上跑過唯讀等級（輸出解析、模型與 token 用量皆正確）。OpenCode v2.0.20 也已跑過唯讀等級。Gemini CLI 目前仍只用模擬 CLI 測試過；發布前需要用真正的 CLI 每個權限等級各跑一次。
- 新的讀取規則與唯讀等級的 skill 載入只用模擬 CLI 測試過，發布前需要用真正的 Claude Code 與 Codex 跑一次 `scripts/real-smoke.sh`。
